# 四类维护实体与可逆迁移

日期：2026-11-16。状态：采用。

## 目标与约束

归档层负责保存来源、原文、原时间、模型结果及局部人工证据。训练收录、发布 head 和段落过滤由制作工程维护，数据结构调整不改变这些职责。

本次将九种维护入口收敛为四类实体，减少同义字段和重复正文。旧 ID、缺省与 null、原输入快照、模型与人工判断、旧哈希和历史产物均须可复验。结构精简不得改写质量结论，也不得静默修补原时间或吞并不同版本。

## 决定

- `items` 保存条目与有序集合；沿用原集合类型、成员顺序、来源编号及视频分 P 关系。
- `documents` 保存转录、整理稿、动态和文章；有限 `kind` 区分语义与校验分支，公共字段不重复表达同一事实。
- `assets` 保存音频、归档描述与已有独立 Markdown/HTML 工件。音频到归档文件的恢复链限于一层；识别块和输入快照如无独立维护需要，继续作为文稿值对象。
- `annotations` 保存文字确认和片段归属。两类证据使用各自的字段与审核规则，适用关系和修订采用依据分开表达。

基础转录、整理稿的分段使用 `blocks`，正文选择器为 Unicode 码点半开区间 `range` 或原文 `literal`，二者恰有其一。全文独立保留，分块无需覆盖全文。块的原粒度、数组顺序与时间值不变。精确重复的序号和计算值按既有公式派生；不同于计算结果的历史断言继续保存。

文稿输入和派生关系使用有限角色的 `inputs`；人工证据使用 `targets`。确认反向列表由证据中的原位置与关系角色投影，不再双写。输入文字只有在来源和片段唯一、源内容哈希与逐字重建均成立时才替换为定位引用。缺映射、歧义和历史快照继续保留。

规范元数据只有证明同义且 JSON 类型、全部观测值精确相同时才合并。原始不同观测、作者与上传者、不同日期含义继续区分。字段名、来源名称相近不构成合并依据。

## 读取与兼容

[机器契约](../schema-v3-contract.json)与 [schema v3 说明](../SCHEMA.md)定义维护格式；[v2 说明](../SCHEMA-V2.md)保留旧字段语义和哈希规范。

读取接口同时提供四类原生记录和九种旧逻辑投影。维护数据只存 v3；兼容层还原旧逻辑值供已有工具、接收批次及历史哈希校验使用。`_legacy` 仅记录字段存在性和有限可逆规则，不保存旧整行或无类型 payload。投影返回真实维护路径，目录、SQLite 和导出属于可重建结果。

核心结构和事实校验不导入专题选择、训练或发布策略；各调用入口组合自己的检查。下游独立读取 v3，不导入本仓库代码。历史提交、入库收据、保存清单和冻结包原字节保留；新保存基线描述新的当前维护集合。

## 迁移与验收

迁移前保存包含未提交改动的工作树快照及逐文件摘要。迁移器从只读源写入独立空目录，验证原生格式、全部引用和工件哈希；逐记录旧格式投影必须与源 JSON 值精确相等。报告包含全部源文件、字段去向、记录映射、哈希和引用。报告先独立核验，再由维护入口整体切换当前数据。

验收覆盖全文、原段文字、输入、时间、顺序、来源、模型、质量和局部证据；还要比较下游 training、full、clean 三种真实输出的字节、计数与配置哈希。旧哈希区分文件字节、规范 JSON 和原文锚点，不因存储改名更换校验对象。

## 代价与后续维护

正文选择器、输入引用和旧投影增加读取逻辑；解释规则集中在格式读取模块，由校验和回归测试约束。旧投影暂时保留九种逻辑名称，维护源仍只有四类。识别块、快照和独立工件保留有意冗余，它们的时间、质量或原格式可能与当前正文不同。

继续增加实体或公共字段前，先核对现有类型和关系能否准确表达。新增 kind、引用角色或配方必须同时更新结构定义、写入限制、校验、迁移与独立消费读取测试，拒绝以无类型属性大桶隐藏字段数量。
