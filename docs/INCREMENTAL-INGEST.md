# 增量更新入口设计

状态：本地批次校验、规划、受限合并、接收凭证和仓库扩展校验已实现；云端投递、生产端 outbox 与自动 PR 尚未启用。命令和验证方法见[维护说明](MAINTENANCE.md)及 [CLI 实现](../src/weimingzi_corpus/cli.py)。

协议、算法、状态机和验收条件见 [详细设计](INCREMENTAL-INGEST-SPEC.md)。
机器可读草案见 [批次 Schema](contracts/ingest-batch-v1.schema.json)。

## 职责边界

`weimingzi-data` 接收外部工作流完成的采集和处理结果，负责把这些结果合入已有维护数据并提出 PR。监听、下载、ASR、对齐、AI 校对、运行队列和失败重试由生产端负责。

仓库侧采用可在本地和 CI 执行的批次命令。生产端向受控发布任务提交交接包；发布任务检出仓库、调用入库命令、运行检查，再推送分支和创建 PR。网络鉴权、存储访问和 GitHub 凭据留在发布任务，入库命令本身只读写本地文件。

服务对象固定为 `chosenecho/weimingzi-data`，默认目标为 Bilibili UID `23191782`。转发、文章与视频参照关系保留实际来源和上传者，不把它们统一改成目标用户创作。配置范围不能代替逐条来源核对。

## 现有能力与缺口

现有 `import --table` 接受 JSON 或 JSONL，在隔离副本校验整库。新增 `ingest` 命令在候选副本合并跨表批次并检查引用。协议和实现见[详细设计](INCREMENTAL-INGEST-SPEC.md)。

本地入口已支持跨表候选、变更预览、冲突报告、应用前基线复查和仓库接收凭证。尚未实现的是交接包对象存储、生产端 outbox、GitHub 受信接收工作流和 PR 状态对账。

## 交接包

交接包由清单和规范记录组成，正文格式沿用 [SCHEMA](SCHEMA.md)，不另建一套语料结构。清单至少包含：

| 字段 | 用途 |
| --- | --- |
| contract_version | 交接协议版本 |
| batch_id | 不可变批次身份 |
| producer | 生产程序及代码版本 |
| source_scope | 平台、目标用户及关联来源 |
| base_commit | 生产端对照的仓库提交 |
| created_at | 批次生成时间 |
| files | 文件路径、字节数和 SHA-256 |
| changes | 目标表、记录 ID 和操作类型 |

`batch_id` 根据清单中的规范内容计算，排除它自身和每次投递变化的传输信息。相同内容重复投递得到相同身份；改变记录或操作后生成新批次。文件路径限于协议允许的数据范围，拒绝越界路径、重复路径和清单之外的文件。生产来源、工作流运行和上游对象编号应可回查，凭据不进入交接包。

交接包可以只包含本次新记录及其对已有记录的引用，不要求它独立构成完整语料库。必须在与目标仓库合并后的候选库中检查所有引用。交接包缺少某条记录，不表示删除该记录。

生产端需固定可复现的 `corpus export` / `corpus verify` 版本及 `--identity-from` 映射，再由适配器把快照转换成消费端变更清单。不能直接用导出的整个 `data/`、空确认表或空选稿覆盖本仓库。

该导出路径目前面向视频、字幕、ASR 和已提交 AI 修订；动态、图文、文章与图片归档仍需采集端另行补齐，最终都使用本仓库同一批次入口。

## 命令与合并规则

本地批次命令：

```sh
python tools/corpus.py ingest verify /path/to/batch
python tools/corpus.py --root /path/to/clean/checkout ingest plan /path/to/batch --report /tmp/ingest-plan.json
python tools/corpus.py --root /path/to/clean/checkout ingest apply /path/to/batch --plan /tmp/ingest-plan.json
python tools/corpus.py --root /path/to/clean/checkout ingest validate-repository
```

`verify` 只读校验批次。`plan` 校验清单、文件哈希及来源范围，对照当前维护记录，输出新增、重复、冲突和拟修改文件列表；不改维护数据。报告绑定批次身份、目标提交和维护输入的内容哈希。规划和应用要求 origin 指向目标仓库、工作区干净，报告保存在检出目录外或被 Git 忽略的 `.cache/` 中。

`apply` 重新核对批次和基线，拒绝套用过期计划；在隔离候选库中一次合入所有表，再运行整库校验和目录生成。只有候选结果通过后才安装到用于发布的独立检出目录。进程或磁盘故障导致安装中断时，该检出目录作废，从干净基线重跑，不能据此推送半批数据。普通逐文件替换不宣称为跨文件原子事务。

合并规则：

- 新 ID：新增；相同 ID 且记录相同：跳过。
- 相同 ID 但内容不同：默认报告冲突，整批不应用，不用后到数据覆盖。
- 元数据和来源补充：使用受限 `enrich` 操作，保留不同观测值；不用通用递归合并。
- 正文变化或新的 ASR、AI 结果：按既有身份约定新增结果，保留原稿及来源关系。
- 删除、人工确认和训练选稿：不由自动采集批次修改。

基线变化后重新规划。互不影响的维护变化可以重新计算后继续；触及同一记录的变化按上述冲突规则处理，不自动选择一方。

## 分阶段交付

采集到的动态、图文和文章正文准备完成即可交付。新视频先交付条目和来源信息，下载、ASR、AI 校对完成后继续提交关联产物；单个视频失败不阻塞其他已完成内容入库。每个交付批次都必须满足完整引用校验。

视频按平台视频及分 P 身份去重，媒体按文件 SHA-256 核对。视频、音频和采集到的图片使用外部媒体存储或 Release；Git 保存文字、结构化记录、清单和可验证的媒体定位。现有音频记录沿用 [音频归档规则](SCHEMA.md)，通过受限操作登记分发定位。视频和图片的定位草案见 [媒体 Schema](contracts/ingest-media-asset-v1.schema.json)，不能仅保存临时播放地址便视为归档完成。

平台字幕、真实音频 ASR 和 AI 整理稿独立保存。AI 结果保留模型、输入关联、完整性和待复核标记，自动入库不能变更为人工审核完成。时间异常按原值保留，由既有校验拒绝不合格的字幕导出。

## PR 与回执

发布任务串行维护该仓库的自动入库分支。一个批次对应可追踪的 PR，重复投递复用已有分支和 PR；无实际差异时返回已存在状态，不创建空 PR。PR 展示来源范围、各表新增数量、重复和冲突、媒体定位、ASR 与 AI 状态及检查结果。

推送范围限于已计划的数据文件和生成目录；发布任务不接收交接包中的代码、工作流或凭据变更。推送前检查当前远端基线，遇到并发更新重新规划，不强行覆盖分支。

发布前执行现有仓库检查：

```sh
python tools/corpus.py validate
python tools/corpus.py generate
python tools/check_repository.py
python -m unittest discover -s tests -v
```

回执区分 `planned`、`pr_open`、`merged`、`rejected` 和 `failed`，记录批次、PR、提交和实际合入的记录身份。PR 关闭未合并不能标记为已入库；重新投递时重新核对远端结果。合并后才能确认仓库接收成功。完整生产日志、失败尝试和重试暂停状态继续留在生产端。

## 上线前验证

批次入口先验证跨表引用、重复投递、同 ID 冲突、过期计划、损坏文件、越界路径、中断恢复，以及对人工维护记录的保留。随后使用一个合成批次完成检查和 PR 流程，再接入真实采集。

采集层还需解决动态列表和视频分页失败，证据由生产端项目保存。列表请求失败时不能将其解释成没有新内容，也不能推进覆盖该页的扫描游标。发现游标、已持久化任务、处理完成和仓库接收分别记账，避免用 PR 成功代替全量发现成功。
