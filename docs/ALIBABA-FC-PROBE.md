- 访问：只有 RAM 鉴权调用，没有创建 HTTP 或定时触发器，也没有配置预留实例。

SDK 的 99 个 Python 文件、52 个 JSON 文件与上游提交 `a0a1566c7c462ab57a3891c3a5f12976cbd11e9e` 比较，全部相同。`EvidenceClient` 继承 SDK 客户端，仅增加域名与读取策略限制、脱敏及证据记录，没有替换 API、WBI、设备初始化或凭据实现。

与 CF 的比较同时改变了运行平台和网络客户端。FC 可用原生 curl，而 CF 使用 Workers fetch 适配，不能将本次差异全部归因于云厂商或出口 IP。

字幕测试读取了实际正文并确认存在非空内容，才标记 `usable`。这里只验证样本正文可读，不代表所有字幕均通过时间戳、归一化或仓库发布质量检查。

## 失败与验证边界

首次创建因 `idle_timeout=60` 小于 FC 要求的 300 秒而被拒绝。函数未创建；核对同名函数仍不存在后，以 300 秒重新创建成功。该失败保存在清单的 `failed_creation` 中。随后仅更新本次创建函数的代码，并核对旧代码校验值；远端配置回读已归档。

新版动态列表是在前置请求通过、实际业务请求已发出后收到 412，区别于此前 CF 的前置阻塞。SDK 的旧版 `User.get_dynamics()` 也做了独立探测，返回 404，没有作为有效替代。视频翻页失败不能解释为没有更多视频。

个别成功调用还包含一个被 SDK 容错忽略的空间页面 412。清单保留完整请求序列，业务调用成功不等于每个前置 HTTP 请求都成功。没有修改 SDK 的容错处理或添加代理。

FC 专用测试 12 项通过，覆盖真实 SDK 方法、WBI、字幕正文、匿名模式、凭据脱敏、风险占位结果及分页参数。仓库原有回归测试 41 项通过。语料、目录和既有失败记录均未改动。

## 凭据与证据

SESSDATA 经隐藏的标准输入设置到 FC 环境变量，没有写入源文件、ZIP 或验证清单。函数没有 RAM 角色，STS 凭据注入设为 `All` 禁用。控制端使用本机既有授权，归档仅保留环境变量名，不保存 AccessKey 或 SESSDATA。

清单保存部署回执、配置回读、健康检查、各批调用、请求 ID、响应哈希和结构摘要。成功原始正文不归档，失败正文仅保存脱敏后前 2000 字符；正文哈希不能用截短摘录复算。原生 curl 先缓冲正文，再检查 2 MiB 接受上限，不具备 CF 适配层的流式截断能力。

目前证据支持用 FC 继续开发已知条目的详情、专栏和字幕补充。要接入自动增量发布，仍需解决视频分页与动态列表，再验证游标、去重、入库及发布回执。此次没有创建生产定时任务或执行仓库写入。
