# 文档重构计划

状态：计划，尚未执行文档合并或迁移。日期：2026-11-17。

本计划针对当前资料仓库。目标是让读者按任务找到唯一的说明入口，减少同一概念、命令和运行状态在多处重复维护。当前事实以 schema v3、uv 环境及实际工具行为为准；历史提案和完成记录按其原日期理解。

## 一、现状与问题

目前 docs 顶层有 17 份 Markdown，其中 [内容目录](INDEX.md) 由工具生成，[v2 结构](SCHEMA-V2.md)和[保存迭代记录](PRESERVATION-ROADMAP.md)承载历史信息，其余 14 份承担当前说明职责。

本次盘点发现的具体问题：

- 维护者需在[维护说明](MAINTENANCE.md)、[增量入口](INCREMENTAL-INGEST.md)和[详细协议](INCREMENTAL-INGEST-SPEC.md)之间查找操作、协议与设计状态；三者需要明确主从关系。
- 查询、导出、专题和覆盖查询分布在[维护说明](MAINTENANCE.md)、[覆盖查询](COVERAGE.md)和[专题说明](TOPICS.md)，同一次查稿任务跨越多个入口。
- 音频下载、保存范围、周期检查和恢复处置分布在[下载说明](DOWNLOAD.md)、[保存说明](PRESERVATION.md)和[运行交接](PRESERVATION-OPERATIONS.md)，应按一次完整恢复流程组织。
- [结构说明](SCHEMA.md)与[名词说明](GLOSSARY.md)分别解释实体、正文、输入和质量语义，需要合并同义定义，保留字段差异与不确定性。
- 部分当前操作仍使用裸 python 命令；[README](../README.md)和[检查工作流](../.github/workflows/checks.yml)已在本轮提交准备中改用 uv，其余操作示例待本计划实施时统一。
- 文件存在性检查不足以发现失效章节链接。例如[维护说明的片段归属段](MAINTENANCE.md#片段归属)仍引用旧结构章节，而当前结构说明已按四实体重新组织。验收需要增加 Markdown 锚点检查。

## 三、写作与一致性规则

1. 当前维护流程以 v3 为主线；旧逻辑表视图与原生维护实体明确区分。实际仍在使用的外部批次协议按代码和机器契约描述，不通过文档改名假定接口已经升级。
2. 一个字段或状态只在结构说明定义一次；操作文档引用定义，说明本步骤如何使用它。缺失、null、false、待复核和人工确认的区别完整保留。
3. 一个命令流程只在所属任务文档完整展开。其他入口提供目的、前提和链接，避免复制整段步骤。
4. 当前可执行命令统一为 uv sync --locked 和 uv run。历史日志、原始引文、历史运行命令保留原字面，并标明历史语境。
5. 当前能力、待实现设计和历史验收结果分别标明状态与依据。计划日期不作为实际完成日期；历史恢复成功不表述为远端永久可用。
6. 操作示例使用可验证的参数和临时输出目录；写操作说明预检条件、成功结果与中断恢复。链接同时检查文件路径和章节锚点。

## 四、实施顺序与交付物

### 阶段 1：固定内容去向

逐节列出上述 14 份当前文档的去向，记录独有规则、有效示例、协议限制、失败路径和证据链接。先处理前文发现的失效章节引用。交付逐节去向清单，确认没有遗漏后进入合并。

### 阶段 2：重写任务文档

依次整理结构说明、维护流程、查询流程、保存流程，再收敛数据卡、协议和验收矩阵。每完成一份即核对源段落，处理重复定义和状态冲突。示例命令的参数以当前 CLI 为准，数据实体与哈希规则以代码、结构声明和机器契约为准。

### 阶段 3：切换导航并移除重复页

更新 README、AGENTS、相互引用和相关源码中的文档链接；移除已迁空的当前说明页。生成目录的链接修正应修改生成逻辑并重新生成，不手工修改生成结果。

### 阶段 4：验证并建立新基线

核对命令、链接、生成结果、历史文件字节和保存范围。同步保存工具中的支持文件清单，然后另建并选择新基线；旧清单、旧事件和旧证据继续保留。

## 五、验收条件

- README 能直接引导到找稿、维护入库、结构、恢复保存和质量限制；AGENTS 能引导维护者完成修改和验收。
- 逐节去向清单全部闭合，独有规则、示例、错误处理和证据入口均有归属。
- 当前示例统一使用 uv，并通过相应 CLI 帮助、临时夹具或只读运行检查；没有指向已移除当前说明页的仓内导航，也没有失效章节锚点。
- 手工说明不复制当前统计量；统计来自生成结果。生成目录与维护数据一致。
- 历史证据、v2 参考、旧保存清单及原事件日志前缀的字节对照无差异。
- 保存范围与实际新文档一致，新基线无缺失、增加或变更，事件链校验通过。
- 文档重构不改变归档记录、人工审核状态、时间值、外部批次协议或已冻结工件。

实施时至少执行下列检查；这些是计划中的重构验收步骤，不代表本文已经执行文档迁移：

```sh
uv sync --locked
uv run python tools/corpus.py validate
uv run python tools/corpus.py generate
uv run python tools/check_repository.py
uv run python -m unittest discover -s tests -v
uv run python tools/preservation_manifest.py check-current --read-only
uv run python tools/preservation_manifest.py verify-log
git -c core.whitespace=cr-at-eol diff --check
```

另外补充 Markdown 章节锚点检查。执行重构时需要读取并核对测试实际结果，不能仅凭链接存在或文档字数下降判定完成。
