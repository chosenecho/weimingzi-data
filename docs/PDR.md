# 未明子资料库 PDR

**版本** v1.0 · **状态** 已确认

## 1. 产品目标

将 `weimingzi-data` 建成可独立使用、持续维护和验证恢复的未明子资料库。查阅者能找到材料、区分版本并回到原文引用。维护者能接收增量、保存不同结果和人工证据，并在交接或故障后核对资料是否恢复到指定版本。[仓库说明](../README.md)

**独立**指本地独立运行。取得指定版本的资料和工具，并准备好锁定的运行环境后，查阅、校验、索引重建和文本导出可在断网环境完成。外部媒体按资产记录恢复，验收时单独核实字节可取得的范围。独立故障域副本不作为交付门槛。[保存、恢复与运行交接](PRESERVATION.md)

**完备**指资料库具备入库、查询、引用、校订、校验和恢复能力，并能说明声明范围内每条已识别材料的保存状况。首版从现有归档建立覆盖基线。评审时明确来源、起止范围、收录类型和盘点依据，再据此列出已有、缺失、部分取得和未知的材料状态。未知状态留待核实。统计按渠道与材料类型分报，并注明盘点日期。[数据卡](DATA-CARD.md)

## 2. 使用者与核心任务

| 使用者 | 核心任务 | 预期结果 |
| --- | --- | --- |
| 查阅者、研究者 | 从标题、平台标识、专题或正文找到资料 | 取得可复核的原文引用，知道来源、版本及质量状态 |
| 维护者、校订者 | 导入新资料、比较多份转录、登记局部核对或修订 | 新旧结果及其依据均可追溯，人工判断精确到适用位置 |
| 接手维护的人 | 在新目录验证或恢复指定版本 | 核对资料字节、重建索引，确认可恢复的媒体及其余缺口 |

## 3. 首版范围与产品入口

首版提供本地命令行、仓内导航及可移植导出。收录对象沿用现有视频与分 P、独立录音、动态、专栏及关联集合。视频和音频可先收录条目与来源，后续补齐媒体定位、基础转录和整理稿。媒体验收沿用现有音频恢复链；其他媒体按现有记录展示观测和可用状态。自动采集与发布、Web 界面、托管查询服务、语义检索和下游训练各自另行立项。[维护与入库](MAINTENANCE.md#分阶段交付) · [查询与导出](QUERY.md)

| 原生实体 | 产品职责 |
| --- | --- |
| `items` 条目 | 记录身份、来源、元数据、关联及集合顺序 |
| `documents` 文稿 | 保存基础转录、整理稿、动态和专栏正文及其生成依据。同一条目的真实不同结果并列 |
| `assets` 资产 | 记录音频、归档包、独立参照稿、HTML 工件及适用的文件校验和恢复位置 |
| `annotations` 人工证据 | 保存局部文字确认及片段归属，明确适用文稿、位置、依据与采用情况 |

四类 UTF-8 JSON/JSONL 记录及资产索引引用的归档工件构成权威资料。SQLite、目录、CSV、字幕及阅读稿由权威资料生成。JSON/JSONL 导出保持原生记录。专题规则用于组织查询。[数据结构](SCHEMA.md#四类维护实体) · [全文检索](QUERY.md#全文检索)

## 4. 首版需求与验收

下列要求用于首版评审。验收记录应标明资料版本、输入、执行结果和证据位置，并列明未覆盖的范围。

### PDR-01 独立读取与重建

使用已准备好的锁定环境，从指定版本在干净目录断网执行资料校验，重建目录和 SQLite，完成全文查询与原生导出。清除派生索引并再次重建后，固定查询样本命中的记录 ID 集合一致。验收记录列明运行环境和需预先取得的文件。

### PDR-02 查找与引用

查阅者可按条目 ID、精确平台标识、专题或正文查找材料。用同一视频的两个分 P 验证直接覆盖和跨来源关联各自指向正确文稿。引用可凭记录 ID、仓库相对路径及字段或块位置回到原文，并核对来源、模型、质量状态以及适用的原时间值和单位。搜索无命中时可查当前索引范围。[找稿与关联](QUERY.md#找稿与关联)

### PDR-03 可审计入库

用合成批次演练校验、候选库规划、应用和回读，并验证接收凭证。原包重投可辨认历史接收状态。分别验证来源或摘要冲突、过期计划在安装前停止，以及写入中断后闭锁并可从干净基线重跑。[增量批次](MAINTENANCE.md#增量批次)

### PDR-04 原文、历史输入与人工证据

抽取一条有多份文稿和局部确认的条目，回查原稿、历史输入快照、锚定文字、适用稿及实际采用稿。单独核对全文复核状态。测试异常时间仍能按原值读取，并确认不符合字幕导出要求的时间值会产生明确错误。[人工确认与局部修订](MAINTENANCE.md#人工确认与局部修订)

### PDR-05 收录盘点与缺口

以注明日期的来源清单为参照，逐条目或分 P 对账，分别报告元数据、基础转录、整理稿、媒体和人工复核的覆盖。每项报告列出适用总数、已有数、缺失数及未知数，并可回查仅有元数据、正文部分取得等具体缺口。媒体单列具备恢复定位的数量和当次字节核验通过的数量。来源未盘清时，覆盖率注明分母仅含已识别条目。

### PDR-06 版本核验与恢复

在新目录按指定基线核验资料及支持文件并重建派生数据。对发布声明中可恢复的音频回读 ZIP、成员和恢复文件，记录范围、字节校验结果及失败项。[保存与恢复](PRESERVATION.md)

### PDR-07 质量状态与内容权利

抽查一份含模型输出的文稿和一份含人工证据的文稿，通过导出的记录或其引用核对来源、质量状态和证据适用范围。未知与明确否定可区分。交付说明附内容权利入口，供使用者逐项核对许可。[数据卡](DATA-CARD.md) · [内容权利说明](../CONTENT-RIGHTS.md)

## 5. 发布与持续运行

首版发布须通过 PDR-01 至 PDR-07 中适用的验收。验收记录固定资料版本、收录范围和实际验证的媒体范围，并列出任何仍未满足的要求。记录查询、索引重建和恢复的耗时、资料规模及运行环境，为后续版本制定性能目标。

持续运行验收要求指定负责人与替补，保留维护机上按计划实际触发的审计记录，并由接手者执行一次只读验证与媒体回读。恢复时间目标和可接受的数据回退窗口视实际运行情况另定。[持续运行门槛](ARCHIVE-ACCEPTANCE.md#持续运行门槛) · [责任交接与保留退出](PRESERVATION.md#责任交接与保留退出)

### 当前依据

现有仓库已记录四实体原生校验、候选库接收、本地查询、保存清单核验和历史音频恢复证据。四实体收口记录中的媒体验证覆盖索引列举和模拟下载回归。历史全量恢复实际覆盖的是当时具备恢复定位的音频。按现有验收矩阵，真实计划触发证据和人员交接仍待补齐，第二保存副本暂缓。[四实体原生处理收口](NATIVE-V3-CLEANUP.md#完成验收) · [资料库验收矩阵](ARCHIVE-ACCEPTANCE.md)
