# 未明子资料库产品开发计划（PDP）

**版本** v0.1 · **状态** 执行草案

## 1. 首版交付

首版面向查阅者、研究者和维护者，交付可在本地独立运行的资料库、仓内导航以及可移植导出。沿用四类原生记录和现有入库、查询、校验及音频恢复工具。开发工作从来源盘点和候选版本回归开始，按验收发现修复缺陷。发布范围和通过条件以已确认的 PDR 为准。[产品需求](PDR.md) · [资料库验收矩阵](ARCHIVE-ACCEPTANCE.md)

本计划按交付依赖排序，具体日期和人员在开发启动时填写。角色暂按维护者负责候选版本与发布、盘点执行者负责收录清单、验收执行者负责回归与回读安排。持续运行阶段由指定的负责人、替补及接手者落实。

## 2. 开发里程碑

### M1 确定盘点口径和验收起点

**负责角色** 维护者与盘点执行者。启动时记录候选提交、保存基线、锁定环境和所需预取文件。以已有归档为起点，列出渠道、来源入口、时间窗、材料类型、盘点日期和依据。先对账一组含分 P、正文和媒体的样本，确认匹配凭据、统计单位和缺口状态。来源范围尚待核实的部分单列。

**交付物** 候选版本记录、来源清单初稿、样本对账结果。样本能按平台标识、分 P 或库内记录 ID 回查，且每项统计的适用范围明确后，启动 M2 和 M3，两项可并行。[收录盘点要求](PDR.md#pdr-05-收录盘点与缺口) · [基线与事件链](PRESERVATION.md#基线与事件链)

### M2 完成覆盖盘点与缺口清单

**负责角色** 盘点执行者。以条目或分 P 对账，分别检查元数据、基础转录、整理稿、媒体和人工复核。对各维度记录适用总数及已有、部分取得、缺失、未知的数量，保留可回查的明细和证据。来源尚未盘清的渠道按已识别条目报告覆盖，另记待核实的范围。媒体恢复定位数在此阶段汇总，实际字节核验数以 M4 的报告为准。

**交付物** 带盘点日期的来源清单、按渠道和材料类型汇总的覆盖报告、可定位到具体记录的缺口清单及补档顺序。汇总数应能从明细复算。缺口按影响分别纳入验收修复或资料补档，发布材料如实列明仍有缺失和未知的范围。[PDR-05 收录盘点与缺口](PDR.md#pdr-05-收录盘点与缺口) · [资料状态说明](DATA-CARD.md)

### M3 跑通本地使用与维护回归

**负责角色** 验收执行者，维护者处理缺陷。用已准备的锁定环境在干净目录断网校验数据，重建目录和 SQLite，运行固定全文查询并导出原生记录。清除索引再建一次，核对固定查询的命中记录 ID 集合。查阅回归覆盖条目 ID、精确平台标识、专题和全文入口，用同一视频的两个分 P 核对直接覆盖和跨来源关联各自指向的文稿，再按 ID、路径、字段或文本块回查引用。记录无命中时可查的索引范围。[PDR-01 独立读取与重建](PDR.md#pdr-01-独立读取与重建) · [PDR-02 查找与引用](PDR.md#pdr-02-查找与引用) · [查询与导出](QUERY.md)

在独立候选目录用合成批次演练校验、规划、应用和回读，核对接收凭证，并重投原包验证历史接收状态。覆盖来源或摘要冲突、计划过期、写入中断后闭锁和干净基线重跑。[PDR-03 可审计入库](PDR.md#pdr-03-可审计入库) · [维护操作](MAINTENANCE.md)

用含多份文稿及局部确认的条目核对原文、历史输入、确认适用稿、实际采用稿和全文复核状态。读回异常原时间值并检查字幕导出错误。[PDR-04 原文、历史输入与人工证据](PDR.md#pdr-04-原文历史输入与人工证据)

通过导出抽查模型文稿和含人工证据的文稿，核对来源和人工证据覆盖范围，确认质量状态能区分未知与明确否定，交付说明可查到权利说明入口。[PDR-07 质量状态与内容权利](PDR.md#pdr-07-质量状态与内容权利)

**交付物** 固定样本清单、断网重建及查询记录、批次规划与回执、异常场景及导出核对结果。每项记录对应 PDR 编号，保留输入、预期、实测和复测结果。

### M4 核验恢复并形成发布记录

**负责角色** 维护者组织发布，验收执行者复核。M2 和 M3 交付齐备后，固定首版候选的提交和保存基线，核对覆盖报告与验收记录是否对应此版本，按改动补做复验。以该版本在新目录只读核验资料及支持文件，复核派生数据重建结果。对发布声明中可恢复的音频，按现有恢复链验证 ZIP、成员和恢复文件的字节数及哈希。逐项保存报告、范围和失败项，并将实测核验数量回填覆盖报告。历史回读仅引用其原范围和版本。[PDR-06 版本核验与恢复](PDR.md#pdr-06-版本核验与恢复) · [全量媒体审计](PRESERVATION.md#全量媒体审计)

**交付物** 首版候选、覆盖与缺口报告、恢复报告、PDR-01 至 PDR-07 验收记录及发布说明。按仓内验收流程核对数据、生成目录、链接、基线和适用回归。发布说明固定版本、收录范围、实际核验的媒体范围及尚未满足的要求，记录查询、重建和恢复的实测耗时、规模与环境。适用要求通过后发布。恢复验收沿用现有音频恢复链。第二保存副本维持暂缓。[本地验收](ARCHIVE-ACCEPTANCE.md#本地验收) · [PDR 发布条件](PDR.md#5-发布与持续运行)

### 持续运行验收

发布准备期间即可安排负责人、替补与接手者。持续运行验收保留本地手动审计和实际计划触发的周检结果，由接手者完成一次只读验证与媒体回读，并归档接收记录。维护者确认失败处置人及访问恢复入口。按 PDR，恢复时间目标和可接受的回退窗口根据实际运行情况另定。[持续运行门槛](ARCHIVE-ACCEPTANCE.md#持续运行门槛) · [责任交接与保留退出](PRESERVATION.md#责任交接与保留退出)

## 3. 执行记录与变更

每项任务记录负责人、当前状态、关联 PDR、交付物和证据位置。候选验收发生失败时，记录受影响的版本、实际结果及复测范围。批准的资料或支持文件变更若影响基线，按保存流程建立并核验新基线，再对受影响的项目复验。收录范围或统计口径有修订时，同步更新来源清单、覆盖报告和发布说明。[维护后检查](MAINTENANCE.md#维护后检查) · [基线建立与验证](PRESERVATION.md#建立与验证)
