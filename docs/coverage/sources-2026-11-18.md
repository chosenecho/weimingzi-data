## 时间口径

时间按字段分别登记窗口。带时区的时间统一换算为 UTC 记录，仅含日期的字符串保持原样，取值为零的 Unix 时间戳排除。窗口边界是本仓记录的观测范围，不是来源平台的完整枚举。视频同时保留 `published_at`、`pubdate`、`ctime`、`date_as_recorded` 等字段，字段间差异不作修补。

## 统计单位

- 1,705 条已关联分 P 的视频父记录只计元数据。其基础转录、整理稿、媒体和人工复核按不适用处理，避免与分 P 重复计数。
- 55 条有独立视频 ID 而在候选中没有分 P 的 B 站视频各作一个后备单位，分 P 数另行核查。
- 1,979 条 B 站分 P、18 条 YouTube 分 P 和 3 条独立录音按单位逐一计数。
- 候选未识别的分 P 不增设单位，也不估算其数量。

## 证据与复算

盘点证据包保存了明细、汇总、样本和缺口台账。用 Python 的 `gzip` 和 `json` 库读取证据包，将 `files` 中各成员的 `text` 按 `encoding` 编码，核对 `size_bytes` 和 `sha256` 后按成员路径落盘。[盘点证据](../evidence/first-release-inventory-2026-11-18.json.gz)

将脚本复制到解包后的 `inventory/`，将已准备环境的候选副本放在同级的 `candidate/`。把全量报告放在候选的 `preservation/checks/` 下，沿用报告文件名。[全量报告](../../preservation/checks/restore-first-release-full-2026-11-18.json)

[生成脚本](scripts/inventory.py) · [回填脚本](scripts/backfill_m4.py) · [复核脚本](scripts/verify.py)

在 `candidate/` 中执行下列命令。`--recount` 从留存明细复算来源窗口、覆盖汇总和缺口台账。`verify.py` 回查记录 ID、路径、行号、正文块和媒体指针。需要重新生成明细或回填时，应另用输出目录保留本轮证据。

```powershell
uv run --offline --no-sync python ../inventory/inventory.py --recount
uv run --offline --no-sync python ../inventory/verify.py
```
